## Deno Deploy EA 首次部署踩坑（01:1x）

用户截图：新版控制台（console.deno.com）里 app `texas-poker` 显示 **Not deployed yet**，
Recent Production Builds 里 `eb15edf` 是**红色失败**。问「点哪里呀」。

**根因**：新版 Deploy 会按仓库内容自动猜测构建命令。仓库根有 `package.json`（Vue 前端）
→ 它去跑 npm install / npm run build，而这跟后端毫无关系（前端早就托管在 GitHub Pages 了）。

**修法**：根目录新增 `deno.json`，用源码配置压过面板自动配置：
```json
{ "unstable": ["kv"], "deploy": { "runtime": { "type": "dynamic", "entrypoint": "./server/main.ts" } } }
```
不写 `deploy.install` / `deploy.build` → 不跑任何安装构建命令，直接把 main.ts 当入口。

**顺带发现的两个硬门槛**：
1. ⚠️ 新版 Deploy 的 KV **必须手动 Provision 再 Assign 给 app**，`Deno.openKv()` 不会自动建库
   （官方 Databases 文档明确写 "not automatically provision"）→ 不分配则部署成功但运行时挂
2. ⚠️ `--unstable-kv` **不能传给 Deploy 运行时**（参数固定）→ 必须靠 `deno.json` 的 `"unstable": ["kv"]`
   本地冒烟时先漏了这个，`Deno.openKv is not a function`，加上后 ping / 空房间读取都正常

**验证**：`deno check` 通过；本地 `deno run -A server/main.ts` 无 flag 启动，
`/api/ping` 返回 `{"ok":true,...}`、空房间返回 `{"ok":true,"snapshot":null}`。

已推送 `deb2457`，触发新一轮构建。

## 让实时同步真正做到「自动」（01:3x ~ 02:0x）

用户问「现在的数据不能自动同步是吧，只能手动点同步」—— 一半对。
之前只有**两处自动**：打开页面时拉一次、结算末尾推一次。
其余改动（改名、删局、改底注、抽卡、导入）落盘后**不会上传**，要等下一局结算才捎带上去。

**改法（不逐个操作点补调用）**：
- `storage.js` 新增 `onLocalChange` / `muteLocalChange` + 内部 `notifyLocalChange`
  —— 在 `savePlayers/saveHistory/saveSettings/saveCards` 四个口子统一广播。
  25 处调用点一个不落，以后新增写入点也自动生效
- `GameDetail.vue`：created 里订阅 → `scheduleLivePush()` **1200ms 防抖**
  （一局结算连写 3 次盘，合并成 1 次请求）；2 秒内刚推过就跳过
- `applySnapshot` 整段包进 `muteLocalChange` —— 数据就是从云端下来的，别再推回去
- `handleWipeData` 改成 async，**先 force 推一份空快照再刷新**
  ⚠️ 顺手堵了个坑：清空数据会把 `poker:cloud` 一起删掉，当时看不出问题，
  但下次连同一个房间码，云端那份旧的会被当成「更新的」拉回来 —— 等于清空失败

**验证**（真实端到端，不是只看单测）：
- 单测 `test-storage-change.js` **17 项**：四个口子都响 / kind 正确 / 落盘失败不响 /
  mute 内不响 / **嵌套 mute 不提前解锁** / mute 里抛错能解锁 / 订阅回调炸了不影响落盘
- 浏览器 E2E（dist 静态服务 + 真线上后端 + 房间 e2eauto1234）：
  1. 注入旧数据后打开页面 → 自动被云端覆盖成「云端来的」（启动时拉取 ✓）
  2. 改底注 10→25 保存 → **没点任何同步按钮**，线上 settings 变成 25（自动推送 ✓）
  3. curl 模拟另一台设备推「另一台加的人」→ 已打开的页面 4 秒内自动跟上（SSE 反向 ✓）
- lint 0 错；全量单测 19 个文件全绿；build 通过（app.js 203.94 KB）
