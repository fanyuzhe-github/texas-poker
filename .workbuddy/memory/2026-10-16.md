# 2026-10-16 德州扑克记账工具改造

## 项目背景
Vue 2.6 + Element UI 2.15 + vue-cli 4 的德州扑克结算工具：选玩家开局随机分座 → 录入剩余筹码 →
自动算出"谁给谁转多少钱" → 更新今日榜与 localStorage 总榜。用户本次要求「修 Bug + 功能增强」。

## 关键发现：项目原本构建不出来
`npm run build` 报 `error:0308010C:digital envelope routines::unsupported`。
根因是 Node 17+ 的 OpenSSL 3 与 webpack 4 的 md4 哈希不兼容。
修复方式：package.json 的 serve/build 脚本加 `NODE_OPTIONS=--openssl-legacy-provider`。
（注意：不加这个前缀，任何构建都会失败。）

## 修掉的 Bug
- App.vue `</style>` 后残留裸字符串 `default.`（会渲染到页面）
- GameStart.vue 106 行死代码，无人引用，已 git rm
- 结算 `allot()` 递归两个致命缺陷：
  1. 赢家被结清后直接 return，后续赢家拿不到钱
  2. 人道模式下输家归零不移除，tolerance 恒为 0 会无限递归爆栈
  → 重写为迭代贪心配对，内部统一用「分」为整数单位
- `data()` 里直接 `JSON.parse(localStorage.getItem())`，数据损坏即白屏
- `playerOptions` 存 Set，Vue 2 响应式支持不完整
- 金额到处是 `(a*100+b*100)/100).toFixed(2)` 脏写法，浮点误差累积

## 新增架构（src/core/）

- `backup.js` 导出 JSON/CSV（CSV 带 BOM 防 Excel 乱码）、导入支持覆盖/合并
- `clipboard.js` 复制降级方案

## 新增组件

回溯结论：原 GameStart.vue 里其实也只有「选择玩家」下拉框，**从来没有独立的新增玩家入口**；
之前重构把它删掉后，用户感知到的"添加玩家"能力缺失就更明显了。本次补齐两条路径。

### 1. PlayerManager.vue 批量新增（主路径）

- 组件根节点由单个 el-dialog 改为 `<div>` 包裹两个 dialog（Element UI 嵌套 dialog 的必要条件）
- 对外 emit `add`，传 names 数组

### 2. GameDetail.vue 下拉框即时入库（副路径）
- 新增 `watch: selectPlayers`：下拉框 allow-create 出来但不在 allPlayers 里的名字**立即写库**，

**教训：回调的 index 语义要明确写进注释，否则调用方极易重复偏移。**

自动选入本局 → 三位新玩家走完开局/录筹码/结算全流程 → 转账方案正确 → 零运行时报错。

## 补：主账号 / 子账号体系（用户需求变更）

用户明确要求：「玩家添加的逻辑保持最开始的样子，一个主账号下可以创建多个子账号，
多个子账号的积分累计给主账号，排行榜的积分使用主账号的」。

经确认的三个设计决策：
1. 主账号**只是分组容器**，不参与牌局；上桌的永远是子账号
2. 排行榜**只列主账号**，可展开看子账号明细
3. 子账号通过**玩家管理里主账号行的「添加子账号」**创建

### 实现方式
- **回退**：删掉上一版的批量新增弹窗与 `parseNames`，恢复到最初「下拉框输名字即创建」；
  但保留 `watch: selectPlayers` 即时入库（否则新建名字在玩家管理里看不到，无法挂子账号）
- **数据模型**：扁平存储 + `parent` 字段（指向主账号名，null 表示自己是主账号）。
  schema 版本升到 3；`normalizePlayer` 补 `parent`；
  `loadPlayers` 清洗失效归属（指向自己/指向不存在的账号 → 降级为独立玩家）
- **可上桌名单** `selectableNames()`：子账号 + 名下无子账号的独立玩家；
  有子账号的主账号是分组容器，从选人下拉里排除

### 最关键的坑：积分归集不能两边都算
第一版把子账号战绩在 `applyOutcome` 里**同时**累计给主账号，展示时 `buildMainRanking`
又汇总一遍 → **胜负场次和积分全部翻倍**（实测 1胜1负 变成 2胜2负）。

**最终方案：`applyOutcome` 只记在实际参与牌局的账号头上，主账号的汇总值一律由
`buildMainRanking` 在展示时实时计算。**
额外好处：子账号「解除归属」时主账号汇总值立刻自动正确，无需回滚历史积分。

### 其他要点
- 今日榜要额外把子账号的主账号也 `ensurePlayers` 进来，否则归集时找不到汇总对象
- `playerFactory` 建玩家时从总库继承 `parent`，避免今日榜丢失主子关系
- 改名时同步改子账号的 `parent` 指向；删主账号时子账号自动升级为独立主账号（战绩保留）
- 转账方案与对局流水**仍用上桌的子账号名**（钱是真人之间的事）
- CSV 导出改为「主账号行 + 子账号明细行」两段式，方便 Excel 查看汇总关系

### 验证
- 归集算法 33 项 node 单测全通过（含"连续两局不翻倍"回归用例）
- 浏览器实测：下拉创建主账号 → 挂 2 个子账号 → 子账号上桌结算 →
  今日榜/总榜汇总正确不翻倍 → 展开明细正确 → 解除归属后汇总自动收敛 → 零运行时报错
- lint / build 通过

## 补：添加主账号入口 + 同一主账号只能出一个号

用户要求：「选择玩家时，只能在主账号和多个子账号中选择一个。现在还没有添加主账号的功能，做一个。」

### 1. 补上"添加主账号"按钮
之前主账号只能靠下拉框输名字隐式创建，界面上没有明确入口。
现在 `PlayerManager.vue` 顶部加「添加主账号」按钮（`$prompt` 输入 + 重名校验），
emit `add-main` → `GameDetail.handleAddMain()` 用 `ensurePlayers` + `playerFactory` 入库（座位号连续）。
主账号的定位再次明确：**名下没子账号时它自己也能上桌；一旦挂了子账号就退化成纯汇总容器**。

### 2. 同组互斥（同一主账号只能出一个号）
新增纯函数 `ranking.js: mainOf(players, name)` 与 `limitOnePerMain(players, names)`：
按「主账号」分组，同组只保留**最后选中**的那个，其余剔除且保持其余项原有顺序。

三层落地：
- **UI 层**：`el-option :disabled="isOptionDisabled(item)"` —— 同组已有号在座时，其余号直接置灰不可点；
  选项右侧用 `.option-parent` 灰字标出归属（如「小张 张三」），一眼看出为什么不能选
- **兜底层**：`watch: selectPlayers` 里再跑一次 `limitOnePerMain`，被顶掉的弹 warning 提示
  （覆盖 allow-create、导入备份等绕过 UI 的路径）；改完自身后 `return`，靠下一轮 watch 继续入库
- **清理层**：`refreshPlayerOptions()` 顺手剔除两类失效选择 —— 已变成容器的主账号、同组重复；
  但**牌局进行中（isPlaying）不清理**，避免桌面座位表与已选名单对不上

### 踩坑记录
- `el-option` 的自定义 slot 内容渲染在下拉浮层里（挂在 body 上），scoped 样式够不着，
  `.option-parent` 必须放在**非 scoped** 的 `<style>` 块里，选择器用 `.el-select-dropdown__item .option-parent`
- 端到端测试时 `agent-browser click <ref>` 的 ref 每次 `snapshot` 都会重新编号，
  跨命令复用旧 ref 会点到别的元素（一度误点成 tag 的关闭 ×，看起来像"选中被莫名清空"）。
  **测这类交互应改用 CSS 选择器或"快照后立刻点击"**，并可用 `eval` 读 Vue 实例状态交叉验证

### 验证
- 新增 14 项单测（`limitOnePerMain` / `mainOf`，含"保留最新选择""剔除后顺序不变""主账号与其子账号同组"）
  → 14 通过 / 0 失败；原有 30 + 33 项回归依旧全绿
- 浏览器实测：添加主账号张三/老王 → 重名被拦 → 各挂子账号 →
  选三哥后小张置灰（带归属标注）→ 跨主账号可多选 → 给老王挂子账号后老王自动移出已选 →
  直接赋值绕过 UI 触发兜底互斥生效 → 三哥+小王上桌结算（小王→三哥 5.00）→
  今日榜张三 +5（含三哥）/ 老王 -5（含小王）不翻倍
- lint / build 通过

## 补：主账号彻底不上桌 + 今日榜按上桌的号排名

用户要求：「让主账号不可以选择，不要出现在玩家选择中，今日排行用今天选择的子账号进行排行」

### 语义收紧（旧行为废弃）
之前"名下没子账号的主账号自己也能上桌"。现在**主账号永不上桌、永不出现在选人列表**。
为了不破坏"下拉框输名字即创建、随即就能上桌"这条铁律，引入第三种账号：

| 类型 | 判定 | 能否上桌 |
| --- | --- | --- |
| 子账号 | `parent` 非空 | 可以 |
| 主账号 | 顶层（`parent` 为 null）且 `isMain === true` | 不可以，只汇总 |
| 独立号 | 顶层且 `isMain` 非 true | 可以 |

- 下拉框现敲的新名字由 `playerFactory` 建成**独立号**，所以"输入即上桌"完全不受影响；
  给它加子账号后 `handleAddSub` 顺手把它的 `isMain` 置 true，自动退化成主账号并从列表消失。
- `selectableNames` = 非 `isMain` 且非容器（挂了子账号的）。
- `refreshPlayerOptions` 额外把"库里存在但不可选"的名字从 `DEFAULT_PLAYER_NAMES` 里过滤掉，
  否则内置默认昵称（三哥 / 老陈等）会把主账号又漏回下拉。

### 今日榜改口径
新增 `ranking.js: buildTodayRanking(todayPlayers, roster)`：直接按今天上桌的号排名
（子账号显示归属小标签），**不做主账号归集**，也不再有展开列
（`RankTable` 新增 `show-expand` prop，今日榜传 false）。总榜仍是 `buildMainRanking` 主账号汇总。
`resetSeat` 里不再往今日榜塞主账号（旧版为了归集才塞，现在不需要）。

### 数据模型
`Player` / `createPlayer` 加 `isMain` 参数；`normalizePlayer` 补该字段；
`loadPlayers` 给"名下有子账号的顶层账号"补 `isMain`（老数据平滑过渡）；schema 4。
`handleDetach` / `handleRemovePlayer` 里子账号升级为独立号时 `isMain=false`；
`handleRename` / `handleDetach` 都要**同时**同步今日榜 `players`，否则归属标签过期。

### 验证

  总榜 老王 +10（子1）/ 张三 -5（子2）/ 老陈 -5，两边口径各自正确 →

## 补：去掉「加买」列，改成每人一个筹码计算器

用户要求：「去掉加买列，给每个玩家配置筹码计算器，分别有四种筹码 1000/500/100/50，
1000 对应 1 筹码、500 对应 0.5、100 对应 0.1、50 对应 0.05，
让玩家输入各个筹码的数量，然后计算出最终的剩余筹码填入剩余筹码中」

### 新增 `src/core/chips.js`（纯函数）
- `CHIP_DENOMINATIONS`：`c1000/c500/c100/c50` → 1 / 0.5 / 0.1 / 0.05 筹码
- `normalizeCount` 数量规整（非数字剔除、空 = 0、最多 6 位）
- `amountOf(count, chipsPerPiece)` 单面值折算
- `chipsFromCounts(counts)` 合计；`countsFromChips(chips)` 反向拆分（大面值优先）；`emptyCounts()`

2. **输光判定 = `chips <= 0 && delta < 0`**：只判 `chips <= 0`，在底注为 0 的脏数据里
   会把所有人误判成输光（人人 0 筹码）。没输过光的人不进榜，而不是显示「0 次」。

### 三个新增的关键口径（踩了会出荒谬结果）
1. **「最惨」类只收确实亏了的（`cents < 0`）** —— 单局最惨 / 当日最惨 / 最惨连败都一样。
   否则一个从没输过的人会以「+1.00」登上「单局最惨」榜。没输过的人不进榜。
2. **翻盘王必须是「输光的下一局」且真的赢回来（`cents > 0`）** ——
   不限定「下一局」，它就退化成变相的单局最高积分（已写成单测锁住）。
3. **连续出勤按自然日去重** —— 同一天打两局只算一天，否则同一晚能刷高「连续天数」。

### 复用与新增
- 复用 `streak.js` 的 `longestLose`（最长连败）与 `worstRun`（最惨连败，亏最多的一段）；
  **这两个不是一回事**：一个看场数、一个看金额，冠军可以不是同一个人（单测已覆盖）
- 新增两个内部 helper：`groupStatsOf`（一局里各主账号的「合计盈亏 + 是否有人输光」）、
  `isBusted`（输光判定统一出口，`collectMostBusted` 也改用它了）、`dayIndex`（自然日序号）
